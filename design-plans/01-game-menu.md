# Тёплое игровое меню с горизонтальными каталогами и пиксельными иконками

Written against: `d35c7ec881eb3d5d0610c37434aeda5d3f30d1df`

Implementation status: реализовано локально; серверная миграция `20261027190242_shared_home.sql` применена. Проверены UI и две мобильные сессии без reload. Реализация включена в релиз общего дома.

## Evidence chain

- Surface: домашняя вкладка `/calendar-duo/` → `src/App.tsx:20` → `Apartment` → `HomeWorkshop` и `PlantNursery`; на входе тот же `Apartment` получает `demo`.
- Problem: пользователь отверг серое выделение игрового меню и сочетание цветов, выбрал горизонтальную прокрутку растений/украшений и пиксельные иконки вместо emoji.
- Design evidence: `src/style.css:22` содержит серые `.night-room` и активный таб; `style.css:27` делает `.nursery-list` вертикальным; `style.css:30` делает мобильный `.decor-grid` одной колонкой. `roomLife.ts` хранит emoji; компоненты выводят их напрямую. Серость подтверждена для ночной оболочки, не для всех состояний. Новая визуальная инспекция не проводилась.
- Owner: `src/components/Apartment.tsx`, `HomeWorkshop.tsx`, `PlantNursery.tsx`, `src/style.css`.
- Scope and affected surfaces: игровая панель, каталоги, награды, погода/комнаты в игре; desktop, mobile и demo на входе.
- Uncertainty: требуется визуальная проверка окончательного вида в Safari и установленном мобильном приложении. Текущего скриншота меню в этом аудите нет.

## Design decision

Панель сохраняет тёплую палитру дома днём и ночью. Ночь меняет сцену, а не превращает управление в серый блок. Растения и украшения выбираются в горизонтальных рядах карточек на всех размерах экрана. Все изображения объектов внутри игрового UI рисуются пиксельными иконками, независимо от платформенных шрифтов emoji.

## Reuse

- `src/style.css`: фон существующего `.interactive-room` — `#ece4d2`; поверхность `.workshop-panel` — `#f8f2e5`; текст и акценты `--ink`, `--muted`, `--green`, разделители `--line` из `:root`. Выбранное состояние взять из существующего `.nursery-list>button[aria-pressed=true]` (`#edf1df`, `#9aa884`) и применять согласованно к обоим каталогам.
- `src/components/Modal.tsx`: оставить владельцем окна посадки и закрытия, не строить второй механизм диалогов.
- Exemplar: `src/lib/roomScenery.ts:44–74` — прямоугольные формы растений/декора и их палитра; `renderRoom.ts` — пиксельная сцена.
- Новый `src/components/PixelIcon.tsx` нужен, поскольку доступные примитивы рисуют только в Canvas и не дают иконок в DOM-карточках. Общие потребители: `Apartment`, `HomeWorkshop`, `PlantNursery`. Набор SVG с целочисленными прямоугольниками и `shape-rendering="crispEdges"`; имена соответствуют существующим ID объектов, а не emoji-строкам. Не нужна внешняя библиотека иконок.

## Changes

1. `src/style.css`
   - Change: удалить серые ночные переопределения оболочки, выбранного таба и управления. Переиспользовать указанную тёплую поверхность и согласованный выбранный вариант; не добавлять ещё один слой конфликтующих переопределений.
   - Preserve: реальную смену времени, затемнение сцены, светильники и осенний пейзаж.
   - Verify: обычная и ночная панель имеют одну палитру управления; ночная сцена остаётся различимой.
2. `src/components/HomeWorkshop.tsx`, `PlantNursery.tsx`, их CSS
   - Change: `.decor-grid` и `.nursery-list` сделать однострочными горизонтальными контейнерами: карточки не сжимаются, не переносятся; прокрутка принадлежит контейнеру. Убрать вертикальную прокрутку каталога видов и мобильное превращение декора в колонку. Имя и кнопка посадки находятся вне прокручиваемого ряда. Прокрутка каталога не двигает сцену и не создаёт горизонтальный overflow всей страницы.
   - Preserve: подписи, имена до 24 символов, выбор вида, признаки установленного декора, требования для открытия, подтверждение посадки и закрытие окна.
   - Verify: первый, средний и последний элементы доступны свайпом; выбранная карточка не сбрасывается при обновлении общих данных. Не менять каталог уже посаженных растений автоматически: пользователь запросил горизонтальный выбор.
3. `PixelIcon.tsx`, `src/lib/roomLife.ts`, игровые компоненты
   - Change: заменить emoji-изображения в карточках, подтверждении, наградах, погоде и выборе комнат на именованные пиксельные иконки. ID видов/декора сохраняются; `nextReward` возвращает идентификатор иконки вместо вставки emoji в текст. Пиксельные изображения согласовать с Canvas-формами кактуса, тыквы, растений, книг, свечей, подушки, привидения и гирлянды.
   - Preserve: читаемые текстовые названия, существующие правила встреч и открытия предметов.
   - Verify: меню не содержит платформенных emoji вместо графики объектов; иконки чёткие на экранах разной плотности.

## Scope

- Inherit: главный дом и demo используют одно исправленное оформление.
- Verify: ночь, закрытые виды/предметы, установленные предметы, пустой сад, заполненная ёмкость, длинное имя.
- Exclude: переделку календаря/истории, изменение цен наград, рост по времени, внешние зависимости. Синхронизация общего дома выполняется отдельным согласованным планом.

## Validation

- Product: открыть украшения, выбрать доступный предмет; в открытой оранжерее выбрать вид, ввести имя, подтвердить посадку.
- Interface: 320, 390, 768, 1440 px; горизонтальные каталоги работают без overflow страницы и без уменьшения крупной мобильной сцены. Отдельно проверить Safari и установленный мобильный web app. Render-проверку запросить/выполнить на этапе реализации.
- System: один PixelIcon и одинаковая палитра выбранных карточек; Canvas не заменять emoji.
- Repository: `npm test` и `npm run build` → успех. В `e2e/playful.spec.ts` заменить ожидание вертикального каталога на горизонтальный (`scrollWidth > clientWidth`) и проверить достижимость последнего элемента. `npx playwright test e2e/playful.spec.ts` → успех с подменой backend, без изменений реальной пары.

## Stop conditions

- Не выдавать локальную запись предмета за подтверждённое сохранение на сервере: зависимость от плана общего дома должна быть выполнена до выпуска.
