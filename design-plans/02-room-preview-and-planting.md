# Выбираемые закрытые комнаты и посадка только в открытой оранжерее

Written against: `d35c7ec881eb3d5d0610c37434aeda5d3f30d1df`

Implementation status: реализовано локально; серверная миграция `20261027190242_shared_home.sql` применена. Проверены UI и две мобильные сессии без reload. Реализация включена в релиз общего дома.

## Evidence chain

- Surface: `/calendar-duo/` → `src/App.tsx:20` → `Apartment` → вкладки комнат, сцена, `HomeWorkshop`, `PlantNursery`.
- Problem: пользователь требует выбирать закрытые спальню и оранжерею, показывая их под полупрозрачной панелью с оставшимся условием открытия. Растения нельзя сажать до открытия оранжереи; посадка и отображение должны находиться в ней.
- Design evidence: `Apartment.tsx:87` задаёт `disabled={locked}`, `goTo` на строке 27 отказывается выбирать закрытую комнату; `room.ts:47` также блокирует переход. При этом `Apartment.tsx:29` и `roomLife.ts:51–55` не проверяют открытие оранжереи/текущую комнату при посадке. `HomeWorkshop.tsx:8,11` предлагает посадку из любого места. `roomScenery.ts:44–54` уже отображает созданные растения только в оранжерее.
- Owner: `Apartment.tsx`, `src/lib/room.ts`, `src/lib/roomLife.ts`, `HomeWorkshop.tsx`, `PlantNursery.tsx`, `roomScenery.ts`.
- Scope and affected surfaces: выбор комнат, закрытый предпросмотр, действия в сцене, создание растений; также demo-потребитель на входе.
- Uncertainty: данные существующих растений могут быть созданы до открытия оранжереи. Их нужно сохранить при миграции, а не удалять.

Это явно выбранное изменение поведения, не находка визуального аудита.

## Design decision

Разделить выбор комнаты для просмотра и право взаимодействовать с ней. Все три вкладки выбираемы; закрытая комната видна под неподвижной полупрозрачной панелью. Текст сообщает порог и остаток встреч. Создание растений разрешено только при открытой оранжерее и в выбранной оранжерее.

## Reuse

- `locations` и `canEnter` из `roomLife.ts`: спальня открывается после 2 завершённых встреч, оранжерея — после 3. Порог не дублировать в компонентах.
- `changeLocation`, `renderRoom`, `drawScenery`: сохраняют существующую геометрию и отрисовку комнат; изменить ответственность `changeLocation`, не копировать сцены для предпросмотра.
- `PlantNursery`, `Modal`, `plantCapacity`, `seeds` и имена растений сохраняются.
- Exemplar: `.game-stage` — существующий позиционный владелец Canvas и overlay-элементов. Новая панель относится к viewport сцены, а не к странице: на телефоне условие должно оставаться видно при горизонтальной прокрутке комнаты.

## Changes

1. `Apartment.tsx`, `room.ts`
   - Change: убрать блокировку выбора закрытых вкладок. Ввести явное состояние «просматриваемая комната» и отдельно вычисляемое право действий. Выбор комнаты локален для каждого устройства.
   - Preserve: существующую сцену каждой комнаты и текущие пороги наград.
   - Verify: при 0 встреч можно выбрать спальню и оранжерею, но нельзя ходить по ним, нажимать мебель/кошку, устраивать действия, ставить декор или запускать локальную генерацию пакостей от просмотра.
2. `Apartment.tsx`, `src/style.css`
   - Change: поверх закрытой сцены разместить полупрозрачную тёплую панель с пиксельным замком. Для оранжереи: «Оранжерея пока закрыта», «Завершите 3 встречи», «Осталось …». Остаток вычислять `max(0, unlock - completedCount)` с корректной формой слова. Существующие табы остаются вне покрытия.
   - Preserve: реальные день/ночь и крупный масштаб сцены.
   - Verify: после третьей завершённой встречи блокировка исчезает автоматически на обоих устройствах без повторного входа и обновления страницы. Пока состояние дома загружается, не показывать недостоверные 0 встреч.
3. `HomeWorkshop.tsx`, `PlantNursery.tsx`, `roomLife.ts`, серверный обработчик посадки из плана общего дома
   - Change: в закрытой оранжерее показывать условие открытия вместо действия посадки. В гостиной/спальне показывать переход «В оранжерею», а не создание на месте. В открытой выбранной оранжерее доступна отдельная посадка через горизонтальный каталог видов и ввод имени. Проверка порога нужна в доменной функции и на сервере, а не только в кнопке.
   - Preserve: кактус и другие виды, индивидуальные ID/имена, ёмкость сада, рост за встречи, существующие растения. Новый guard не должен сломать чтение старых сохранений.
   - Verify: прямой вызов действия до 3 встреч отклоняется; запрос после открытия проверяет вид, имя и свободное место. Созданное растение отображается в `drawScenery` оранжереи и в её общем списке, не появляется в гостиной/спальне.

## Scope

- Inherit: все входы в посадку и все пути взаимодействия с закрытой сценой.
- Verify: состояния 0, 1, 2, 3 встречи; открытие по обновлению сервера; выбор другой комнаты вторым человеком не перемещает первого.
- Exclude: новые комнаты, смену стоимости открытия, авто-завершение встреч, удаление старых растений.

## Validation

- Product: 0 встреч → выбрать закрытую оранжерею → увидеть условие; 3 встречи → посадить именованный кактус → увидеть его в оранжерее.
- Interface: панель читается на 320/390/1440 px и остаётся в видимой области сцены; вкладки доступны для перехода назад; меню не даёт выполнить запрещённые действия.
- System: единый `locations.unlock`; сервер принимает решение об открытии на основании завершённых встреч, а не клиентского счётчика.
- Repository: `npm test`, `npm run build`, `npx playwright test e2e/playful.spec.ts` → успех после изменения сценариев. Существующий тест, ожидающий `isDisabled()` у спальни, должен проверять выбранную заблокированную сцену. Тест роста должен сначала иметь открытие оранжереи, затем проверять только встречи после посадки.

## Stop conditions

- Если для предпросмотра требуется менять общий дом или начислять события, сначала отделить локальное навигационное состояние.
- Если серверные данные ещё не доступны, не разрешать посадку по неподтверждённому localStorage-счётчику.
